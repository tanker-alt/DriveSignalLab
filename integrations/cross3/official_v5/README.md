# PressLight CARLA v5

独立优化适配器；不修改 `official/`、上游 PressLight 或 v4 输出。仍使用官方 SimpleDQNAgent 的 80 维网络、四动作和优化器，但 **Bellman 目标是修改后的半马尔可夫目标，不能称为未修改的官方训练算法**。

## 时间与目标

保留全部灯态同步、黄灯 3 秒、全红至少 2 秒、车辆及车尾清空、释放后 5 秒绿灯规则。无需通过削减安全间隔改善指标。沿用原压力奖励，不加入年龄或左转奖励。

以 10 秒为时间基准，令 `gamma=.8`：

```
R = integral_0^duration gamma^(t/10) * pressure_reward(t) dt / 10
Y = R/20 + (1-terminal) * gamma^(duration/10) * max Q_target(next_state)
```

逐仿真 tick 的常数奖励使用解析积分，对 tick 拆分不敏感。一次决策的每秒成本以及后继价值折扣均计入实际黄灯、延长全红和绿灯时间。最后一辆车完成且没有后续到达时是真终止；超时是截断，保留 bootstrap（有意学习持续交通价值，未加入倒计时状态）。schema=2 字典记录时长、积分回报、平均奖励、折扣和终止/截断，拒绝混用旧列表 replay。

## 采集、探索与消融

每个训练种子目标 18,000 条进入 replay 的经验，约为 v4 的 10 倍；每批至少 300 条再更新，累计 1,000 条前不更新。每条决策以累计经验数计算 epsilon，从 .8 线性降至 .1，12,000 条时到达下限。普通训练场景持续到达 600 秒，最多再清空 300 秒，降低原先短到达、长清空对样本的支配。更新可能超过 300 条边界，因为仅在完整场景结束后训练；最后按总预算截取 replay，原始场景仍完整保存。

三个变体均使用相同网络、经验预算、探索曲线、训练到达长度和验证协议：

- `legacy`：旧平均奖励、固定 .8 折扣、无终止屏蔽；这是匹配新采集预算的目标消融，不是逐字复现 v4。
- `smdp`：只修正时长积分/折扣及终止处理。
- `smdp_coverage`：修正目标，并以每第五个训练场景替换为晚到单车，覆盖四动作、两侧入口和四种初始相位的 32 种组合；其余场景仍含四种常规流量。

种子 2026、2027、2028。先验证时间目标，再比较覆盖方案。训练样本的场景组成、epsilon 和更新次数应随结果同时报告；覆盖消融改变数据分布而不是奖励。未引入强制轮转、防饿死规则或优先 replay。低车流补充是否有效需要实验，不能预先保证。

验证：新种子 8401–8404 四种常规流量，另加 32 个晚到单车组合；按总体未完成比例优先、场景平均等待其次选模。单车平均等待与常规流量应另行报告，避免等权聚合掩盖某一组退步。可选最终测试用新的 9401–9406，只有冻结超参数后才使用 `--final-test`。不复用已经曝光的 7101–7106。若在最终测试后调参，必须另留测试集。


不得在现有训练占用时启动；入口 `load_map` 拒绝同步世界或任何车辆/传感器/行人，v5 runner 另有按端口的非阻塞锁。仿真只能顺序执行。程序不 kill CARLA，不接管已有同步场景，不支持跨协议恢复；输出目录必须全新。`check_live.py` 仅做四种运动的小规模环境/replay/训练契约检查，不是性能或全安全回归的替代品。

所有训练自动冻结协议和本版本源码。待三种子实验结束，比较完成率、平均等待（含入口等待）、四动作频率、切换损失和种子间方差；性能改善尚未证明。

完整顺序套件：`python suite.py --output <全新目录>`；先查看计划可加 `--plan-only`。汇总：`python summarize.py <套件目录>`。套件不默认开启最终测试，失败后停止安排后续任务，不终止外部进程。单车验证是刻意复用结构的覆盖诊断，不应当作新的独立泛化证据。

## 离线审查修订（先不训练）

worker 新增兼容 Keras 2.2 的最佳 val_loss 权重恢复，失败或无有限 val_loss 时拒绝保存。仅按固定30%拟合验证分割选择epoch，**不是交通rollout选模**，也不保证控制性能改善。每次更新另外保存目标版本、抽样 replay 索引、更新前四动作Q、奖励、时长、gamma_eff、终止标记、TD目标/误差和epoch验证历史；初始化权重保存为initial。`--target-lag-updates`显式指定目标延迟，默认仍5，未擅自调参。修订不支持恢复旧replay训练，以免混入原来未保存初始/最佳epoch的协议。

`offline_audit.py --input <先导目录> --output <新目录>`只读已有模型生成32个固定单车特征探针、全部实际验证状态的Q/TD及覆盖统计，不导入CARLA、不拟合模型。`probe` worker IPC可对给定schema=2样本计算Q/TD而不更新参数。探针中的合成单车状态用于特征/Q响应检查，不能代替闭环验证；没有实际转移就不虚构对应TD目标。

当前覆盖最低门槛为每组合至少4条观察到该入口车辆的经验、且至少1条执行该需求动作；这是可配置的工程下限，不代表充分学习。先导只有2/32通过。正式消融仍不应启动：先完成覆盖配额设计及冻结协议，后续经用户决定才采集或训练。未自动增加等待年龄、改变奖励、缩短安全时间或运行新实验。

覆盖配额修订：`plan_coverage.py`和`coverage_quota.py`采用12条入口有车观察/4条正确需求动作/4条替代动作的筛查门槛，替代前述低门槛。`train.py`、`suite.py`正式运行前要求`--coverage-plan`且重算门槛；当前0/32，不得启动。此门槛没有自动收集或读入训练数据的含义；还需实现独立采集和冻结数据接口。具体缺口及未执行消融方案见 `Drive/outputs/cross3/official_v5_coverage_plan_20261025/NEXT_STEPS.md`。
